# BE-U1000 на плате EVU-BA-2.1 — справочник по железу

> Первоисточники: «Микроконтроллер BE-U1000. RM v.0.90.6 ALFA», «Техническая
> спецификация v.1.5.5», «Отладочная плата EVU-BA-2.1. Техническое описание
> v.2.1.2» (далее ТО платы), SDK 2.1 и 2.3.
> Ревизия платы, на которой всё проверялось: **EVU-BA-2.1**, ядро 0, 25 МГц
> без PLL. Числа с пометкой «измерено» получены на ней.

Часть I — что за железо. Часть II — как с ним работать.

---

## 1. Обзор

EVU-BA-2.1 — базовая отладочная плата под BE-U1000: все 48 линий GPIO выведены
на три гребёнки, есть QSPI flash 16 МБ, отладчик FT2232HL на плате (он же
USB-UART), разъёмы плат расширения Arduino UNO и выбор режима загрузки
перемычками.

Из предыдущих ревизий (EVU-BA-1.2, 2.0) плата отличается обозначениями
разъёмов и схемой питания — конфигурации OpenOCD в SDK 2.1 есть для `1_2` и
`2_0`, для `2_1` отдельной нет.

## 2. Кристалл

| | |
|---|---|
| Корпус | QFN-88, 10×10 мм, контактная площадка снизу (`VSS`, вывод 89 — паять обязательно: земля и теплоотвод) |
| Ядро 0 | CloudBEAR BR-350, 200 МГц, `rv32imafcn…`, ABI `ilp32f` |
| Ядро 1 | CloudBEAR BR-350P, 200 МГц, то же + DSP-расширения, ABI `ilp32f` |
| Ядро 2 | BM-310, 100 МГц, `rv32imc_zicsr_zifencei_zba_zbb_zbc_zbs`, **без FPU**, ABI `ilp32` |
| eFlash | 256 КБ, `0xA0000000` |
| TCMA / TCMB | 64 КБ `0x40010000` / 96 КБ `0x40020000` (у ядра 2 — 2 КБ `0x40007800` и 8 КБ `0x40008000`) |
| SRAM | 32 КБ, `0x70000000` — **выборка команд оттуда не идёт** |
| QSPI0 / QSPI1 | окна `0x80000000` / `0x90000000`, по 16 МБ; на плате микросхема на QSPI1 |
| АЦП | три 12-разрядных SAR, 1 MSps, входы `VIN0…VIN7` **общие на все три** |
| Импульсные | 4 × PWMA (16 бит), 2 × PWMG, 2 × TIM (32 бита, 4 канала) |
| Шины | 2 × CAN FD, 4 × SPI (ведущие — только SPI1 и SPI3), 4 × I2C, до 7 UART, 2 × I2S, USB 2.0 OTG, PIB |
| Прочее | DMA, CLIC, WDT, PIO |

Тактирование: **осциллятора у кристалла нет**, на вход `CLKI` подаётся готовый
генератор. На плате это G1 25 МГц. PLL: выходная частота 260…1300 МГц
(техспец. §«Система синхронизации»). Внутренний RC-генератор включается
перемычкой `CLK`.

⚠ **Диапазон внутреннего генератора в документах разный:** техспецификация
кристалла v1.5.5 называет **12…32 МГц** (трижды: сводка, таблица параметров,
описание системы синхронизации), ТО платы v2.1.2 п. 3.10 — **20…40 МГц**.
Разрешить это по бумагам нельзя, на плате не мерено. Практического значения
пока нет: рабочий режим — от `CLKI`, а внутренний генератор нужен только как
резерв и для блока мониторинга внешнего синхросигнала.

## 3. Разъёмы, перемычки, кнопки, светодиоды

| Обозначение | Назначение |
|---|---|
| **XS1** «USB OTG» | USB 2.0 самого BE-U1000; через него идёт DFU. Может питать плату |
| **XS2** «JTAG UART0» | FT2232HL: JTAG-отладчик **и** USB-UART (UART0). Основной рабочий кабель |
| XS3…XS6 | разъёмы плат расширения Arduino UNO |
| XP5 | UART0 отдельной гребёнкой |
| XP6 | внешний JTAG-отладчик (или вывод отладчика платы наружу) |
| XP7 | GND |
| **XP8** | порт C целиком (`PC0…PC15`), входы АЦП `VIN0…VIN7`, питание, `RST_U`, `RST_ALL` |
| **XP9** | порт A целиком (`PA0…PA15`), `AREF` |
| **XP10** | порт B целиком (`PB0…PB15`), 3V3 |
| **XP1** | выбор режима начальной загрузки: `M0`, `M1`, `M2`, `DBG`, `CLK` |
| **XP11** «PWR SEL» | выбор источника питания: `USB` / `EXT5V` / `VIN` |

Кнопки: **SB1 «USER»** — на `PC13`; **SB2 «RESET»** — аппаратный сброс МК и
микросхемы QSPI flash. Светодиоды: **LD1 «USER»** зелёный — на `PC0`,
**LD2 «POWER»** белый — индикация 3,3 В.

### 3.1 Режимы начальной загрузки (ТО платы, табл. 3-3)

Перемычка установлена = 1. Порядок в таблице — `DBG-M2-M1-M0`.

| Перемычки | Режим | Что делает |
|---|---|---|
| `0000` | EFLASH | исполнение программы из eFlash |
| `0001` | UART | BootROM CLI через UART0 |
| `0010` | QSPI | исполнение из QSPI flash на интерфейсе QSPI1 |
| `0011` | USB | запись образа через USB DFU либо CLI через USB CDC |
| `0100` | JTAG EXT | отладчик на плате или внешний |
| `0101` | PYTH UART | встроенный MicroPython через UART0 |
| `0110` | MULTI | поочерёдно: EFLASH, QSPI, USB CDC, UART |
| `0111` | FACT RST | сброс параметров памяти к заводским |
| `1001` | USB/UART | поочерёдно: USB, UART |
| `1100` | JTAG INT | встроенный JTAG-отладчик BE-U1000 |
| `1101` | PYTH USB | MicroPython через USB CDC |

Перемычка `CLK`: **снята** — генератор G1 25 МГц (норма), **установлена** —
внутренний RC 20…40 МГц.

Соответствие выводам кристалла (техспец. табл. 3-5): `MODE[0]` = `PA10`,
`MODE[1]` = `PB10`, `MODE[2]` = `PC4`, `DBG` = `PC8`, `CLK_STRAP` = `PC6`.
Внутри все подтянуты **вниз** через 42 кОм, поэтому «ничего не установлено» —
это EFLASH от `CLKI`. Единица задаётся внешним резистором не менее 1 кОм.

### 3.2 Питание (ТО платы, рис. 3-4, табл. 3-2)

| Положение XP11 | Напряжение | Источник |
|---|---|---|
| `USB` | 5 В | XS1 (USB OTG) либо XS2 (JTAG UART0) |
| `EXT5V` | 5 В | внешний источник 5 В |
| `VIN` | 10…48 В | внешний, через предохранитель FU1 1,5 А и DC/DC |

5 В понижаются LDO до 3,3 В на кристалл и на выводы `3V3` разъёмов. Домены
1,7 В и 1,2 В кристалл формирует внутренними LDO, 1,0 В (`VREF`) даёт отдельный
источник на плате. Питание отладчика FT2232HL и его EEPROM идёт **отдельным
LDO от XS2** — отсюда практическое следствие: без кабеля в XS2 отладчик и его
линия сброса мертвы, даже если плата запитана иначе.

### 3.3 Сброс (ТО платы, рис. 3-5)

`RST_MCU` формирует логика DD10 по любому из сигналов:

- `RES_BUT` — кнопка SB2;
- `RST_U` — внешнее устройство через XP8 контакт 14;
- `RST_ALL` — внешнее устройство через XP8 контакт 26, через супервизор с
  задержкой 200 мс, **и сбрасывает заодно отладчик**;
- `SRST` — от отладчика на плате или внешнего через XP6;
- `DTR_RESET` — от FT2232HL.

Все сигналы сброса активны низким уровнем. Последний пункт — причина того,
что **любое открытие `/dev/ttyUSB0` перезагружает плату**: драйвер поднимает
модемные линии при каждом открытии.

## 4. Карта выводов на гребёнках

Полная матрица альтернативных функций — ТО платы, рис. 3-6 (XP9), 3-7 (XP10),
3-8 (XP8). Ниже — соответствие «вывод → контакт», которое нужно каждый раз, и
функции, проверенные на плате.

### 4.1 XP9 — порт A

| Вывод | Контакт | Вывод | Контакт |
|---|---|---|---|
| `PA0` | 1 | `PA8` | 17 |
| `PA1` | 2 | `PA9` | 11 |
| `PA2` | 4 | `PA10` | 15 |
| `PA3` | 6 | `PA11` | 13 |
| `PA4` | 3 | `PA12` | 18 |
| `PA5` | 5 | `PA13` | 19 |
| `PA6` | 8 | `PA14` | 14 |
| `PA7` | 10 | `PA15` | 16 |

`AREF` — контакт 7, `GND` — 9, 12, 20.

Занято и проверено: `PA0…PA4` — **JTAG платы** (`TCK`, `TMS`, `TDO`, `TDI`,
`TRST`); `PA6`/`PA7` — `UART0_TX`/`RX`, АФ #1 (тот самый порт, что идёт на USB);
`PA8…PA11` — **SPI1**, единственный доступный ведущий (`CSN`, `SCK`, `MOSI`,
`MISO`); `PA12`/`PA13` — `PWMA0_CH2P`/`CH2N`, АФ #4, комплементарная пара с
аппаратным мёртвым временем; `PA14`/`PA15` — `CAN0_TX`/`RX`.

⚠ `PA10` — страповый (`MODE[0]`) и он же `SPI1_MOSI`.

### 4.2 XP10 — порт B

| Вывод | Контакт | Вывод | Контакт |
|---|---|---|---|
| `PB0` | 1 | `PB8` | 13 |
| `PB1` | 2 | `PB9` | 14 |
| `PB2` | 3 | `PB10` | 16 |
| `PB3` | 19 | `PB11` | 18 |
| `PB4` | 6 | `PB12` | 5 |
| `PB5` | 8 | `PB13` | 7 |
| `PB6` | 15 | `PB14` | 9 |
| `PB7` | 17 | `PB15` | 11 |

`3V3` — контакт 10, `GND` — 4, 12, 20.

Проверено: `PB8` — `PWMA1_CH0P`, АФ #4 (захват); `PB10` — `PWMA1_CH1P`, АФ #4
(второй канал захвата) **и страповый `MODE[1]`**; `PB9` — `PWMA1_CH1P` по АФ #5,
альтернатива для `PB10`, если страп мешает; `PB12`/`PB13` — `TIMER1_PWM0`/`PWM1`
(резерв под ШИМ, когда блоки PWMA заняты); `PB6`/`PB7` — `CAN1_TX`/`RX`;
`PB8…PB11` — ведущий **SPI3** (то есть SPI3 и захват претендуют на одни выводы).

**На порту B из блоков PWMA есть только PWMA1** — это и определяет, что захват
живёт здесь, а вывод импульсов на порту C.

### 4.3 XP8 — порт C, АЦП, питание

| Вывод | Контакт | Вывод | Контакт |
|---|---|---|---|
| `PC0` | 1 | `PC8` | 10 |
| `PC1` | 2 | `PC9` | 11 |
| `PC2` | 3 | `PC10` | 13 |
| `PC3` | 4 | `PC11` | 15 |
| `PC4` | 5 | `PC12` | 17 |
| `PC5` | 6 | `PC13` | 21 |
| `PC6` | 7 | `PC14` | 23 |
| `PC7` | 9 | `PC15` | 25 |

Аналоговые входы: `VIN0` — 28, `VIN1` — 30, `VIN2` — 32, `VIN3` — 34,
`VIN4` — 36, `VIN5` — 38, `VIN6` — 35, `VIN7` — 37. `AREF` — контакт 7 разъёма
XP9. Питание и служебное: `3V3` — 12 и 16, `5V_EXT` — 18, `VIN` — 24,
`RST_U` — 14, `RST_ALL` — 26, `GND` — 8, 19, 20, 22, 27, 33; контакты 29 и 31
не подключены.

Проверено: `PC5`, `PC7`, `PC9`, `PC11` — `PWMA2_CH0P…CH3P` (АФ #3, #3, #3, #2);
`PC15`, `PC8`, `PC6`, `PC4` — `PWMA3` (АФ #4, #5, #5, #4). `PC0` — светодиод
LD1, `PC13` — кнопка SB1.

⚠ Три вывода порта C страповые: `PC4` (`MODE[2]`), `PC6` (`CLK_STRAP`),
`PC8` (`DBG`). ⚠ `PC0…PC3` у кристалла несут **альтернативную** разводку JTAG
(`JTAG_TCK`, `TMS`, `TDO`, `TDI` — функция #3, RM рис. 5-20), а `PC11…PC14` —
её же по функции #5. На этой плате ни та, ни другая не используется: JTAG сидит
на порту A. При переносе на свою плату это надо помнить.

⚠ **Опечатка в RM.** В таблице функций порта C (рис. 5-20) поле для `PC[4]`
указано как `IOAFCR4[20:18]`, хотя соседние идут с шагом 4 разряда
(`[14:12]` у `PC[3]`, `[22:20]` у `PC[5]`) и перекрываться не могут. По шагу
правильное поле — `[18:16]`. Кода это касается только там, где регистр пишется
руками, минуя `CRU_PIN_Init()`.

### 4.4 Arduino UNO (XS3…XS6)

`XS4` — аналоговые входы `VIN0…VIN5`; `XS5` — `PA13`, `PA12`, `PA8`, `PA10`,
`PA11`, `PA9` (то есть SPI1 и пара PWMA0), `AREF`, `PA5`/`PA4` (I2C0);
`XS6` — `PB7`, `PB6`, `PB8`, `PB15`, `PB14`, `PB13`, `PB12`, `PB2`;
`XS3` — питание и `RST_U`.

## 5. Карта памяти

| Область | Адрес | Размер | Замечание |
|---|---|---|---|
| TCMA | `0x40010000` | 64 КБ | **единственное исполняемое ОЗУ** |
| TCMB | `0x40020000` | 96 КБ | данные |
| Front port | `0x50000000` | 256 КБ | |
| SRAM | `0x70000000` | 32 КБ | данные и межъядерный обмен; **команды отсюда не выбираются** |
| QSPI0 | `0x80000000` | 16 МБ | на плате не разведена |
| QSPI1 | `0x90000000` | 16 МБ | микросхема на плате, XIP |
| eFlash | `0xA0000000` | 256 КБ | зерно стирания: сектор 1 КБ, блок 8 КБ |

У ядра 2 карта своя и крошечная: TCMA 2 КБ по `0x40007800`, TCMB 8 КБ по
`0x40008000`, доступа к eFlash, SRAM и QSPI у него нет вовсе (в `mem_map.mk`
они обнулены).

Регистры: `EFLASH_CR` и прочее — `0xA1000000`; `CRU->SYSCR0` — `0x14000018`,
и его разряд 31 (`DMAMODDIS`/`DAMODDIS`) запрещает модификацию eFlash **прямым
доступом**. Отсюда шаг `14000018:1w` у BootROM: он пишет флеш обычными store.
Регистровому тракту снятие защиты не нужно — проверено, стирание и запись при
взведённой защите проходят.

# Часть II — как с этим работать

## 7. Система сборки

Проект — это Makefile, который подключает `Tools/build/common.mk`. Основные
переменные:

| Переменная | Значение по умолчанию | Зачем |
|---|---|---|
| `SDK_DIR` | `../..` от проекта | путь к SDK; в шаблоне задаётся через `BAIKAL_SDK` |
| `BOARD` | пусто | `EVU_BA_2_1` — подключает BSP и определяет макрос платы |
| `CORE_NUM` | `CORE_0` | ядро: от него зависят ISA, ABI, стартовый код и допустимые области памяти |
| `MEM_REG_ROM` | `EFLASH` | куда линкуется код: `TCMA`, `TCMB`, `EFLASH`, `QSPI1` |
| `MEM_REG_RAM` | `SRAM` | `TCMA`, `TCMB`, `SRAM` |
| `SRC_AUTOSEARCH` | `1` | 1 — обход всех подкаталогов, 2 — только корень, иначе только `CSRC` |
| `CSRC`, `INC_DIR` | пусто | явные исходники и пути заголовков |
| `BUILD_TYPE` | `debug` | подкаталог в `output/` |
| `FLOATING_POINT_MODE` | `HARD` | `SOFT` для ядра 2 выставляется само |
| `MATH_VER` | `IN_ROM` | математика из ПЗУ; `STANDARD` — из тулчейна |

Результат — `output/debug/<имя каталога>.{elf,bin,hex,lss,disasm,sym}`.
**Имя образа берётся из имени каталога проекта**, а не из переменной.

Три вещи, которые ломают сборку молча (см. правила 9, 10 в `SKILL.md` и
предупреждения в `template/Makefile`): зависимости заголовков, переиспользование
`generated.ld`, и файл с именем `main.c`, состязающийся с `main.c` из
`Projects/_template`, если тот попал в список исходников.

## 8. Прерывания и CLIC

```c
CLIC_Config(1U, 1U);   /* по одному разряду на уровень и на приоритет */
__enable_irq();
```

Дальше на каждый источник:

```c
CLIC_ConfigIRQ(CLIC_PWMA1_IRQn,
               CLIC_INTATTR_MODE_MACHINE,
               1U, 1U,                       /* уровень и приоритет */
               CLIC_INTATTR_SHV_VECTORED,
               CLIC_INTATTR_TRIG_TYPE_LEVEL, /* по уровню, а не по фронту */
               CLIC_INTATTR_TRIG_POL_P);
CLIC_EnableIRQ(CLIC_PWMA1_IRQn);
```

**Запуск по уровню, а не по фронту** — для блоков со своей защёлкой запроса
(PWMA, PWMG): по фронту событие, пришедшее между гашением флагов и
подтверждением приёма, пропало бы целиком.

Имена обработчиков обязаны совпадать с таблицей векторов
(`Tools/build/platform/BE_U1000/startup_c0_c1.S`): `UART0_IRQHandler`,
`TIM0_Channel0_IRQHandler`, `PWMA1_IRQHandler`, `DMA0_IRQHandler`,
`CANFD0_IRQHandler`, `ADC0_IRQHandler`, `WDT0_IRQHandler` и так далее.
Объявляются они как `void __attribute__((interrupt)) Имя(void);`.

**Вложенности нет.** Обработчик GCC входит с закрытым `mstatus.MIE`; уровни
задают только порядок выбора среди ожидающих. Измеренный провал главного цикла
на реальной нагрузке — 850…1300 мкс при самом длинном обработчике 460…501 мкс:
остальное набегает очередью. Периодическая работа, которую ведёт цепочка
«прерывание заряжает следующее событие», не должна опираться на остаток
периода — она встанет в очередь за самым длинным обработчиком.

## 9. Поваренная книга

Код — в `reference/recipes.md`, здесь только то, что надо знать до кода.

**GPIO.** Два слоя: `CRU_PIN_Init()` задаёт вывод (порт, подтяжка, входной
буфер, сила, альтернативная функция), `GPIO_Init()` — направление. Забытый
`InputCtrl = ENABLE` даёт «мёртвый» вход при исправном источнике.

⚠ **Слоёв на самом деле три, и третий забывается чаще всех: тактирование
самого порта.** Оно включается отдельно и отдельно для каждого порта —
`CRU_APB0_PERIPH_GPIO0` (порт A), `CRU_APB1_PERIPH_GPIO1` (B),
`CRU_APB2_PERIPH_GPIO2` (C), — и нужно даже тогда, когда вывод отдан
альтернативной функции, а не GPIO. Без него `CRU_PIN_Init()` проходит молча, а
периферия вывода не видит. Измерено на плате 2026-08-31: захват PWMA1 на `PB8`
не считал ничего, пока не включили тактирование порта B; выход PWMA2 на `PC5`
при этом работал, потому что порт C уже тактировался ради светодиода — то есть
отказ прятался за посторонней подсистемой.

**TIM** — временная база. 32 разряда, считает **вниз**, тактируется от PCLK0.
Наружу отдаётся дополнение счётчика; старшие 32 разряда ведутся программно.
Между переполнением и его обработкой есть окно, в котором время скакнуло бы
назад на 2^32 тика — читатель обязан проверять `RAWINTSTAT` сам.

**PWMA** — захват и импульсы. 16 разрядов, на 25 МГц окно 2,62 мс. Один вектор
прерывания на все каналы блока. Подтверждение — `PWMA_ClearIT()` последней
строкой. Захват: `PWMA_IC_Config()` + фильтр `PWMA_IC_FILTER_FDIV1_N8` (отсекает
короче ~320 нс); метка переводится на общую шкалу вычитанием возраста защёлки:
`метка = now() − (счётчик_сейчас − защёлкнутое)`, с поправкой на отношение
частот APB2 и APB0. Импульс: два совпадения (`ACTIVE`, потом `INACTIVE`),
предзагрузка **выключена**; для ШИМ, наоборот, включена.

**ADC + DMA.** Группа рангов, запуск программный, `ADC_DMA_Enable()`,
прерывание — только от DMA. Линии `hardware handshake`: 13 (`ADC_0 RX`),
15 (`ADC_1 RX`). ⚠ **Приёмник обязан лежать в SRAM:** DMA не имеет доступа ни к
TCMA, ни к TCMB (измерено 2026-08-31 по трём адресам — `RAW_ERR = 1` и канал
гаснет сам, без флага завершения). Измерено: 18 мкс на канал, 0 потерь из 500, смещение нуля на
закороченном входе — ноль. Одновременной выборки нет: разброс по времени между
первым и последним каналом группы из шести — 90 мкс.

**UART.** Единственный порт на USB — UART0 (`PA6`/`PA7`, АФ #1). Подтверждения
приёма прерывания не требует: линия опускается сама при чтении `IIR`, разборе
FIFO, чтении `LSR` или `USR`. Обработчик обязан крутиться по `IIR` до «нет
запросов» (иначе при запуске по уровню — бесконечный вызов). `BUSY_DETECT`
взводится записью в `LCR` во время передачи (то есть при смене скорости) и
снимается **только** чтением `USR`. Аппаратная FIFO — 16 байт.

**SPI.** Ведущими умеют быть только SPI1 и SPI3. Доступен практически SPI1
(`PA8…PA11`), потому что SPI3 сидит на выводах захвата. Линия выбора кристалла
у контроллера одна — второй ведомый требует GPIO. Проверять настройку чтением
`BAUDR` и `SER` обратно.

**CAN FD.** Тактовая 12,5 МГц (`CANx2CLK/2`). Кванты считать. `ICR` писать
**до** `IER`. Разбирать по `ISR`, а не по `SR` (аксессора для `ISR` в SDK нет).
Фильтр «принимать всё» ставить при открытии. Трансивера на плате нет — проверка
только `CANFD_OPMODE_LOOPBACK`.

**eFlash.** Сектор 1 КБ, блок 8 КБ. Измерено из TCM: стирание сектора 3261 мкс,
блока 4061 мкс, запись слова 50,4 мкс (в RM `tPROG` 8 мкс — это лишь один
интервал последовательности). Из приложения те же операции дали 8253 и 105 мкс;
расхождение не объяснено, обе цифры приводятся рядом. Блоком стирать выгоднее в
6,4 раза. Код записи — из TCM.

**WDT.** Период до 335 мс, режим с прерыванием даёт 670 мс до перезагрузки и
возможность узнать причину. Обработчик истечения **не должен** снимать запрос.
Однажды включённый, блок выключается только системным сбросом. Регистра причины
сброса нет: отметку держать в ОЗУ, которое стартовый код не трогает.

## 10. Прошивка, отладка, оживление

### 10.1 BootROM CLI по UART0 (основной путь)

XP1: установлена только `M0`. Кабель в XS2. Скорость 115200 8N1.

```
d                       вход в CLI
14000018:1w             снять защиту eFlash
a0000000:40000:0:100m   адрес : максимальный размер : 0 : настройки тактирования
:::101m                 стереть
:::3L                   ждать образ (ROM шлёт 'C' — XMODEM с CRC-16)
<XMODEM, блоки по 128 байт>
a0000000g               запустить
```

⚠ В штатной инструкции размер в команде записан константой `22800` — это размер
TCM, попавший в пример для eFlash по недосмотру; для eFlash он вчетверо занижен,
и образ больше 138 КБ так не записать.

В TCM: тот же порядок без `14000018:1w` и без `:::101m`, адрес `40010000`,
команда загрузки `l`. Пропадает при снятии питания — удобно для первых проб.

Сброс перед сеансом отдавать линией DTR (кнопка не нужна). 256 КБ по UART идут
около 25 секунд.

### 10.2 USB DFU

XP1 в `0011`, кабель в XS1: `dfu-util --alt 2 --download образ.bin`. Быстрее для
больших образов, но для сброса нужен **второй кабель** в XS2 — питание FT2232HL
идёт оттуда. Для доступа без root нужно правило udev на устройство DFU.

### 10.3 JTAG

XP1 в `0100` — отладчик на плате (тот же FT2232HL, кабель в XS2) либо внешний
через XP6 (тогда питание — любое, кроме XS2). XP1 в `1100` — встроенный
JTAG-отладчик кристалла.

OpenOCD из SDK: `Tools/OpenOCD`, конфигурации
`board/baikal/evu_ba_2_0.cfg` (для ревизии 2.1 отдельной нет),
интерфейсы `debug/interface/{evu-ba_ftdi,ft2232h-jtag,jlink-jtag,olimex-jtag}.cfg`.
Внешний отладчик выбирается переменной `EXTERNAL_DEBUGGER`. Сброс сконфигурирован
как `trst_and_srst srst_pulls_trst`.

### 10.4 Заголовок образа и кодовое слово BootROM

Система сборки SDK кладёт в начало образа заголовок в 48 байт
(`Tools/build/ldscript_template.ld`):

| Смещение | Содержимое |
|---|---|
| `0x00` | `0x0300006F` — `jal x0, 48`, перепрыгнуть заголовок |
| `0x20` | кодовое слово области (`__HEADER_MAGIC_NUM__`) |
| `0x28` | адрес копирования |
| `0x2C` | размер копирования (`LOADADDR(.data) + SIZEOF(.data) − LOADADDR(.text)`) |
| `0x30` | начало кода |

Кодовые слова (`Tools/build/service.mk`):

| Область | Кодовое слово |
|---|---|
| `EFLASH` | `0x0BEF5262` |
| `TCMA` | `0x0B10D522` |
| `TCMB` | `0x0B10DDA2` |
| `QSPI1` | `0x00000000` |

BootROM в режиме `EFLASH` читает `0xA0000020`, сверяет с `0x0BEF5262` и при
совпадении передаёт управление на `0xA0000030`; **не совпало — уходит в режим
`USB`** (руководство пользователя §3.2.1).

Проверено на собранных образах шаблона: под eFlash первые байты —
`6f 00 00 03` (`jal x0, 48`), по `0x20` лежит `62 52 ef 0b` = `0x0BEF5262`, по
`0x2C` — размер образа; тот же проект под `MEM_REG_ROM=TCMA` даёт по `0x20`
`22 d5 10 0b` = `0x0B10D522`. То есть отличить образ одной области от другой
можно одним `xxd -l 0x30`, не запуская его на плате. Поэтому «залил и не стартует» почти
всегда означает не испорченную плату, а образ, собранный под другую область
либо не системой сборки SDK.

### 10.5 Оживление

Испортить плату прошивкой нельзя: режим загрузки задаётся перемычками **до**
сброса и от содержимого eFlash не зависит. Оборванная заливка — это негодный
образ, не более: вернуть XP1 в `UART` и залить заново. Режим `FACT RST`
(`0111`) сбрасывает параметры памяти к заводским.

## 11. Признак → причина → лечение

| Признак | Причина | Лечение |
|---|---|---|
| Плата «зависает» сразу после разрешения прерывания | у блока не подтверждён приём: PWMA/PWMG требуют `PWMA_ClearIT()` (разряд 15 `DIER`) | подтверждение — последней строкой обработчика |
| Прерывание срабатывает ровно один раз | то же, но запуск в CLIC настроен по фронту | подтверждать приём **и** ставить `TRIG_TYPE_LEVEL` |
| Регистр состояния в обработчике читается нулём, а обработчик вызывается | защёлка запроса живёт за флагами | см. выше |
| АЦП отдаёт часть рангов и замолкает | подтверждение прерывания пишет в `CR1` и обрывает последовательность | перейти на DMA, прерывание АЦП не разрешать |
| АЦП «зависает» в инициализации | ожидание `ADC_IsCalibrationOnGoing()`, которое никогда не кончится | убрать ожидание; `CAL_SEL` — выбор источника |
| Все отсчёты нулевые при исправных входах | из результата вычтен «ноль калибровки» 1400…1700 | не вычитать |
| CAN: кадры уходят, ответов нет, ошибок нет | `CANFD_RequestMode()` не дождалась режима, `CEN` снят | повторять запрос до подтверждения `GetMode()` |
| CAN: шина не открывается вовсе | число квантов не делит `12,5 МГц / скорость` нацело | считать кванты, а не брать 16 |
| SPI: `Init` успешен, обмен по таймауту, `TXFLR = 1` | это ведомый блок (SPI0 или SPI2) | взять SPI1 или SPI3; читать `BAUDR`/`SER` обратно |
| Захват не считает ни одного фронта: провод исправен, регистры таймера верны | не включено тактирование **порта GPIO** — оно отдельно от тактирования периферии | `CRU_APB1_EnableClock(CRU_APB1_PERIPH_GPIO1)` для порта B (A — APB0/GPIO0, C — APB2/GPIO2) |
| АЦП «нет результата», хотя `ADR` меняется: `RAW_ERR = 1`, `CH_EN` сам обнулился, флага завершения нет | приёмник DMA лежит в TCM, а DMA туда не достаёт | буфер в SRAM `0x70000000`; при сборке под TCM — `MEM_REG_RAM=SRAM` |
| Вывод обрывается на середине строки | ядро в трапе с запрещёнными прерываниями: выборка команд из SRAM либо долгая критическая секция над флеш-памятью | исполнять из TCM; не ждать флеш в критической секции |
| Функция, положенная в ОЗУ, не возвращается | `0x70000000` не исполняемое | копировать в TCMA `0x40010000` |
| Прошилось, но не стартует | образ собран под другую область: `generated.ld` переиспользован | `make clean`, проверить `ORIGIN` |
| Залилось, плата не виснет, но программа не идёт; появляется устройство USB | BootROM не нашёл кодового слова по `0xA0000020` и ушёл в режим USB | собирать образ системой сборки SDK и под ту область, куда льём (§10.4) |
| Правка заголовка не влияет ни на что | зависимости `*.o.d` не подключены | `-include $(wildcard $(OBJ_DIR)/*.o.d)` или `make clean` |
| Приложение работает, но консоль пуста | в режиме `EFLASH` BootROM UART не поднимает | поднимать порт самому |
| Плата перезагружается при каждом подключении | ADBUS4 FT2232HL на цепи сброса | это неустранимо со стороны ПК; учитывать в протоколе |
| Собранная своя плата уходит в чужой режим загрузки | подтяжка вверх на страповом выводе | убрать; страпы тянуть только вниз |
| Импульс короче заказанного ровно на 2,62 мс | в регистре сравнения осталось значение прошлого фронта | переставлять `CCR` при каждой перезарядке |
| Захват даёт кратный период и произвольную скважность | пропущен фронт: между фронтами меньше 100 мкс | один фронт на канал либо два канала с разной полярностью |
| `float` в обработчике портит вычисления в главном цикле | GCC сохраняет только используемые им регистры | целые в прерываниях, плавающие — в главном цикле |
| Сборка под ядро 2 падает на `string.h` | у тулчейна нет libc для `rv32imc/ilp32` | свои `memset`/`memcpy`, без `<string.h>` |
